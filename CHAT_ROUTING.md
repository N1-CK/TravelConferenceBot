# Разделение переписок по отделам

## Этапы

1. **Выбор отдела.** Кнопки PR, Event и Travel сохраняют активное направление пользователя в PostgreSQL. После перезапуска бота выбор остаётся. Если направление ещё не выбрано, бот предлагает выбрать его перед отправкой обычного сообщения. Меню можно открыть и сменить направление в любое время.
2. **Маршрутизация.** Новое сообщение получает отдел при сохранении и отправляется только в Telegram-группу этого отдела (`TG_PR_MANAGER_CHAT_ID`, `TG_EVENT_MANAGER_CHAT_ID`, `TG_TRAVEL_MANAGER_CHAT_ID`). Если группа не настроена, сообщение доступно в веб-панели, но не пересылается в общую группу. Ответ из веб-панели сохраняется в том же диалоге, из которого отправлен.
3. **Разделение доступа.** В веб-панели чаты имеют ключ `(user_id, department)`. Список, история, файлы, отметка прочтения, отправка, архив, папки и отключение уведомлений проверяют отдел менеджера на сервере. Администратор видит все отделы.

## Обновление действующей базы

При запуске добавляются таблица выбранных направлений и колонка отдела сообщений. Старым сообщениям нельзя достоверно определить отдел, поэтому их история остаётся в разделе **LEGACY**, доступном только администратору и только для чтения. Существующие вопросы PR, Event и Travel остаются в своих отделах. Старые личные отметки архива, папок и непрочитанного остаются в LEGACY; новые отметки разделены по отделам. Перед обновлением на рабочем сервере сохраните резервную копию PostgreSQL и перезапустите бот и веб-панель.

## Проверка на сервере

1. Пользователь выбирает Travel и отправляет текст и фото: оба появляются только у Travel и в его группе Telegram.
2. Пользователь переключается на PR: следующий текст попадает только в PR; Travel видит только прежние сообщения.
3. Менеджер Travel отвечает через веб-панель; ответ виден только в истории Travel. Прямой запрос к истории PR из сессии Travel возвращает `403`.
4. После перезапуска бота новое сообщение остаётся в последнем выбранном направлении; старые сообщения проверяются администратором в LEGACY.

Автоматическое назначение конкретного менеджера внутри отдела в этом изменении не вводится: разделение происходит на уровне команд.
